# Workflow Module

Current phase and exact next task are always in:
`docs/progress.md`

Do not maintain a second competing phase tracker here.

At phase end:
1. validate,
2. update `docs/progress.md`,
3. update architecture/protocol docs if needed,
4. record tests and known issues,
5. write the next exact task,
6. compact only after state is persisted.

Development sequence is defined by the actual progress file and approved plan, not by a generic hard-coded phase list in this module.
