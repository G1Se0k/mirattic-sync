- 원인: 멤버 엔진(`SyncFollower`)은 0.5~1.5초 차이를 고치지 않고 지켜보기만 함(허용 범위). 엔진이 위치를 맞추면(`currentTime`) 플레이어는 그 지점을 불러오는 동안 멈춰 있고 방은 계속 가므로 늦게 도착하는데, 비활성 창에서는 크롬이 탭 우선순위를 낮춰 이 지연이 1초를 넘음 → 맞춘 직후 차이가 허용 범위에 떨어져 굳음. 엔진은 맞춘 뒤 다시 확인은 했지만 허용 범위면 아무것도 안 했음
- 수정: 엔진이 위치를 맞춘 뒤 5초 동안은 도착 위치를 확인 — 아직 0.5초 이상 차이 나면 빗나간 만큼 앞을 목표로 다시 맞춤(최대 2번, 앞당김은 3초 이내). 그 밖의 허용 범위 차이는 그대로 둠(작은 차이마다 맞추면 영상이 자주 멈칫함). 그 5초 안에 멤버가 직접 옮긴 0.5~1.5초도 맞춤(방은 호스트만 조작)
- 보완(첫 수정 후에도 증상이 남는다는 확인): 영상이 바뀌면 멤버 엔진은 탭이 아직 이전 영상이라 "다른 영상"으로 끝내고, 탭이 새 영상을 늦게 불러와(또는 자동 재생이 미뤄지거나, 재생 중이라면서 버퍼링에 멈춰) 늦게 출발할 때 1.4초 뒤에서 시작 — 엔진이 한 번도 맞추지 않아 첫 수정의 도착 확인도 작동하지 않았음. 이제 호스트 상태를 받으면 확인 창을 엶: 플레이어가 그 영상에서 방과 같은 재생 상태(재생 · 정지)가 된 순간부터 5초, 그 안의 0.5초 이상 차이는 맞춤(처음 1번 + 빗나가면 2번, 맞출 수 없는 Netflix 제외). 빗나간 만큼 앞당기는 보정은 엔진이 직접 맞춘 뒤에만(늦게 출발한 차이에 쓰면 앞지름). 버퍼링이 1.5초를 넘으면 차이가 커져 기존 위치 맞춤 구간에서 처리됨 — Codex 지적 두 번(자동 재생 미뤄짐, 버퍼링) 반영. 확인 창 안의 1.5~3초 차이도 같은 횟수 제한 안에서 맞추고, 맞출 때마다 횟수를 새로 채우지 않음(늘 2초 모자라게 도착하는 플레이어가 끝없이 맞추던 반복, Codex 세 번째 지적)
- 테스트: sync — 1.46초 늦게 도착하는 플레이어, 늘 1초 늦게 도착(두 번만 다시 맞추고 멈춤), 새 영상이 탭에서 1.4초 늦게 시작, 늦게 시작 + 맞춤도 늦게 도착, 자동 재생이 미뤄졌다 1.4초 뒤 스스로 재생, 재생 중이라면서 1.4초 버퍼링 → 모두 맞춰짐, 늘 2초 모자라게 도착 → 바로는 3번만 맞추고 그 뒤는 예전처럼 약 1초에 한 번. 각 재현 테스트는 그 전 단계 코드에서 -1400~-1460ms "허용 범위"로 실패해 증상을 재현함
- 알려진 한계: 실제 두 계정 · 비활성 창 재현은 크롬에서 직접 확인 필요. 확장만 바뀜(다음 스토어 버전부터)

- 멤버가 호스트를 저절로 따라갈 때(같은 묶음 · "항상 허용" · 묻지 않기 설정)는 따라가는 탭의 링크만 바꾸고 탭을 활성화하지 않음(`open(url, false, quiet)`). 사용자가 누른 "이 영상 열기"는 지금처럼 앞으로 가져옴
- 방 기록: 영상이 끝나고 다음 영상이 저절로 시작되면 "영상을 바꿨습니다" 한 줄만 — 영상 끝(길이 2초 안)의 일시정지는 10초 붙잡아 그 사이 다음 영상이 오면 버림(안 오면 일시정지로 씀), 영상이 바뀐 뒤 10초 안의 첫 재생이 시작 위치면 쓰지 않음(처음의 멈춤 보고는 건너뜀). 알려진 한계: 그 10초 안에 호스트가 직접 처음부터 재생해도 기록 안 됨(자동 재생과 구분할 신호 없음)
- 타임스탬프는 그 영상에서만(결정 102): 위치 있는 채팅 · 기록에 방 영상 ID를 숨겨 저장(V22 `content_key`), 지금 방 영상과 다르면 눌러도 이동 안 함. 채팅 입력 옆 "타임스탬프 찍기"(시계) 버튼 → 창에서 시간 확인 · 수정 후 찍기 → "○○님이 12:34에 스탬프를 찍었습니다" 기록(호스트는 눌러서 이동). 개인정보처리방침(문서 · privacy.html)에 반영
- 고정한 인식 탭을 다른 창으로 옮겨도(분리 · 다른 창에 넣기) 계속 인식(결정 101). 이전의 `stopped`(창 이동으로 인식 중단) 상태는 삭제
- 방 기록: YouTube 재생바를 놓은 순간 아직 멈춰 있어도 바로 "일시정지"로 쓰지 않고 잠깐(1초) 더 기다림 — 곧 재생되면 "이동" 한 줄만(전에는 "일시정지" + "재생"). 영상 변경 기록의 제목이 늦게 읽히면("YouTube") 같은 기록을 진짜 제목으로 고쳐 다시 보냄(새 줄 없음)
- 채팅: 삭제 버튼이 있는 줄(내 메시지 · 방장)도 다른 줄과 같은 높이. 패널로 돌아올 때(내 정보 다시 읽기) 방 화면이 다시 그려지던 문제 수정 — 로그아웃 콜백이 렌더마다 새로 만들어져 소켓이 다시 연결되던 것
- 멤버가 여는 YouTube 링크는 일반 영상 링크(결정 100): 재생목록 · 믹스(`list=`)를 붙이지 않음. 같은 재생목록 다음 영상 자동 따라가기는 유지
- 표시 이름은 Mirattic Auth 이름으로 동기화(결정 99): 로그인 · 내 정보 조회 때 맞춤. 친구 목록 · 방에는 다음 조회부터 (실시간 알림 없음). 패널은 다시 포커스될 때(Auth 탭에서 돌아올 때) 내 정보를 다시 읽음. 테스트: MiratticLoginTest(Auth에서 바꾼 이름 반영 · 이름 없으면 유지 · 재로그인)
- 설정 맨 위 "계정 정보 수정" → 새 탭으로 https://auth.mirattic.com/ (Mirattic 계정 자체는 Auth에서 수정; 따라가는 탭으로 쓰이지 않게 `window.open`)
- 설정 "피드백 및 버그 리포트" → 종류(의견 · 제안 / 버그 신고) + 내용(2000자) → 서버 `feedback` 테이블(V21), 하루 10건. 개인정보처리방침(문서 · privacy.html)에 항목 추가
- 설정 공개 범위의 "재생 위치" 삭제, 서버가 친구에게 재생 위치를 항상 숨김(이전에 친구 공개였던 사람도). 동의 화면 문구 보완(버전은 그대로)
- 분리 패널: 인식할 탭을 고르면 그 탭을 활성화하고 그 창을 앞으로. "사이드 패널로 돌아가기"는 인식 중인 탭의 창으로(없으면 마지막 브라우저 창), 그 창을 앞으로 가져옴
- 테스트: 서버 SafetyFlowTest(피드백 저장 · 공백/종류/길이 400 · 비로그인 401 · 하루 한도 429 · 계정 삭제 시 삭제), PresenceViewTest(친구 공개여도 위치 숨김), watch(분리 중 고른 탭 활성화)
- 알려진 한계: 동기화 끄기 · 피드백 화면은 자동 테스트 없음(크롬에서 확인 필요). 끈 동안에도 탭 인식(기기 안)은 계속되지만 서버로는 아무것도 보내지 않음. 피드백에 확장 버전 · 브라우저 정보는 자동으로 붙지 않음. **서버 배포 필요**(V21, presence 변경) — 확장보다 먼저 배포해야 피드백 보내기가 404가 나지 않음

### 패널을 별도 창으로 분리 (2026-10-03, 사용자 요청, 결정 97)
- 홈 · 방 화면 위쪽 버튼 "창으로 분리" → 같은 패널 화면을 팝업 창(`sidepanel.html?detached`, 420×760)으로 열고 사이드 패널은 한 창 규칙(결정 94)으로 닫힘. 분리된 창의 "사이드 패널로 돌아가기" → 마지막으로 포커스된 브라우저 창에 사이드 패널을 열고 분리된 창은 닫힘
- 분리 중에는 한 창이 아닌 모든 브라우저 창의 탭 기준: 활성 탭 = 지금 포커스된 브라우저 창의 활성 탭(뒤에 있는 창에서 저절로 바뀐 활성 탭은 아님), 고정 탭이 다른 창으로 옮겨져도 계속 인식, 닫힌 탭의 대체 · "이 영상 열기"의 기존 탭 찾기도 모든 창(원래 창 우선), 목록에서 다른 창 탭을 골라도 패널 이동 · 앞으로 가져오기 없음
- 분리 중에는 "이 창에서 보시나요?" 토스트 없음(분리되는 순간 떠 있던 것도 내림)
- 테스트: watch +2(포커스된 창의 활성 탭 따라가기 · 토스트 없음 · 사이드 패널로 돌아오면 다시 제안, 고정 탭 창 이동 유지 · 다른 창에서 대체)
- 알려진 한계: 크롬에서 직접 확인 필요(팝업 창 · `sidePanel.open` 동작은 자동 테스트 없음). 분리된 창의 크기 · 위치는 기억하지 않음. 분리된 창을 닫은 뒤 패널이 없는 동안에도 모든 창 기준이 유지됨(다음에 사이드 패널을 열면 그 창 기준). 워커가 재시작될 때 분리 모드는 패널의 다시 연결(hello)로 복구. 분리 중 브라우저 창을 모두 닫아 팝업만 남으면 "이 영상 열기" · 사이트 열기 · "사이드 패널로 돌아가기"가 동작하지 않음(새 브라우저 창에 포커스하면 복구)

### "이 창에서 보시나요?" 토스트는 방 호스트에게만 (2026-10-03, 사용자 요청, 결정 95 보완)
- 다른 창으로 패널을 옮기자는 토스트는 참여 중인 방의 호스트일 때만(그 방에서 활성 탭을 따라가는 중일 때) — 방 밖, 방 멤버에게는 보이지 않음. 보낼 때 · 다시 보낼 때 · 누를 때 모두 다시 확인하고, 호스트가 아니게 되면(호스트 넘김 · 방 나감 · 방 종료 · 다른 기기로 교체) 떠 있던 토스트는 다른 알림처럼 바로 내림(`TOAST_DISMISS`)
- 패널 목록에서 다른 창 탭을 골라 옮기는 것은 그대로(누구나)
- 알려진 한계: 백그라운드 자동 테스트 없음(토스트 조건은 background.ts에 있음) — 크롬에서 직접 확인 필요. 워커 재시작 직후 방이 다시 로드되기 전에는 제안 안 함

### 재생 속도 동기화 · 영상 없는 방의 "이 영상 열기" (2026-10-03, 사용자 요청, 결정 96)
- YouTube · Netflix · Laftel 모두 호스트의 재생 속도로 멤버가 재생 — 속도만 바꿔도 호스트가 `playback:seek`(같은 위치 + `rate`)를 보냄, 서버 V20 `rooms.playback_rate`, 위치 외삽은 경과 × 속도(서버 · 클라이언트 · 호스트 이탈 일시정지)
- 멤버가 속도를 바꾸면 되돌림(일시정지처럼). 속도를 계속 되돌리는 페이지와는 1초에 한 번만 다시 맞춤
- 방 타입이 다른 사이트로 바뀌어 그 사이트 영상이 아직 없는 방에서는 이전 사이트 영상의 "이 영상 열기"를 보이지 않음 (영상이 아예 없는 방은 원래 보이지 않음)
- 테스트: sync-core +3(멤버가 호스트 속도로 · 자기 변경 되돌림 · 위치 유지, 되돌리는 페이지와 싸우지 않음, 호스트가 속도 변경을 보내고 그 속도로 외삽), 서버 RoomFlowTest(속도 전달 · 없으면 1 · 범위 밖 / 문자열 거부)
- 알려진 한계: 실제 사이트에서 직접 확인 필요 — YouTube 설정 메뉴의 속도 표시가 `<video>` 속도와 다르게 보일 수 있음, Netflix · Laftel 플레이어가 외부 속도 변경을 되돌리는지 미확인(되돌리면 1초마다 다시 맞춤). 이전 버전 호스트(속도를 보내지 않음)의 방에서는 멤버가 1배속으로 맞춰짐

### 패널 안내 남은 시간 · 탭 바꿀 때 일시정지 (2026-10-03, 사용자 요청)
- "패널 열기" 안내(10초)의 남은 시간 막대가 30초 기준으로 그려져 3분의 1에서 시작하던 문제: 토스트에 그 알림의 전체 시간(`total`)을 실어 막대가 그 비율로 시작(다시 그려도 남은 비율 유지). 다른 알림은 그대로 30초 기준
- 인식할 탭을 다른 탭으로 고르면(같은 창 · 다른 창으로 옮기기 모두) 그때까지 인식하던 탭의 영상을 일시정지 — 연결을 끊기 전에 그 탭 플레이어에 pause를 보냄(이미 멈춰 있으면 그대로, 끊긴 뒤라 방에는 전해지지 않음). 활성 탭 자동 따라가기로 탭이 바뀔 때는 하지 않음(사용자가 고른 경우만)
- 보완(Codex 1차): pause는 고른 탭이 확인된 뒤에만(그새 닫힌 탭을 고르면 지금 탭은 그대로 · 멈추지 않음) — 이전 연결은 선택 즉시 끊기므로 그 탭에 따로 짧게 연결해 보냄(`pauseTab`)
- 테스트: extension +2(다른 탭을 고르면 이전 탭에 pause, 같은 탭을 다시 고르면 안 함 — 되돌리면 실패 확인; 닫힌 탭을 고르면 pause 없음)
- (Fable 검증) 탭을 고르는 조회 중에 이전 탭 사이트(Netflix/Laftel)의 제어를 끄면 그 탭에 pause를 보내던 틈 수정 — 이전 탭의 사이트를 함께 기억해 pause 시점에 켜져 있을 때만 보냄(끈 사이트는 절대 조작하지 않음). 테스트 +1(되돌리면 실패 확인). 그 외(pause 전달 순서 · 방으로 새지 않음 · 옮기기 · 자동 따라가기 · 토스트 막대 다시 그리기)는 결함 없음

### 다른 창으로 패널 옮기기 (2026-10-03, 사용자 요청, 결정 95 보완)
- 크롬은 사이드 패널을 사용자 동작(클릭 · 단축키)에만 열어 줘서 탭 전환으로 자동으로 열 수는 없음 → 사용자 클릭을 쓰는 두 경로:
  - 패널의 인식할 탭 목록에서 다른 창의 탭을 고르면 그 클릭으로 그 창에 패널을 엶(선택을 먼저 보낸 뒤 열기, 이전 창 패널은 한 창 규칙으로 닫힘)

## Architecture Decisions
- `docs/architecture/plan.md` 결정 1–11 유지
- 12. ID는 앱에서 생성한 UUID 문자열 (`VARCHAR(36)`). TS 타입의 `string` id와 일치
- 13. 친구 요청과 친구 관계를 `friendships` 한 테이블(status)로 관리
- 14. 친구 관계 변경은 `friend:update`(payload 없음)만 보내고 클라이언트가 다시 조회. 변경 내용을 이벤트로 동기화하지 않음
- 15. Presence 공개 규칙은 순수 함수 `PresenceService.view`에 모음. 차단하면 친구 관계가 삭제되는 것으로 차단자에게 presence가 가지 않음을 보장
- 16. Desktop 상태 관리는 React state만 사용. Zustand / TanStack Query는 아직 필요 없어 도입하지 않음
- 17. JWT 라이브러리를 따로 쓰지 않고 Spring Security OAuth2 resource server에 포함된 Nimbus 사용
- 20. 친구 추가는 친구 코드로만 (이메일 검색 제거)
- 19. 사용자는 UID(`users.id`)로만 식별하고, 로그인 수단은 `user_identities`로 분리 (OAuth 대비)
- 21–28 (Phase 2): mock provider, playback/version DB 저장, 초대=멤버십, `room:update` 후 재조회, 서버 시각 기준 `capturedAt`, seek 구간 재확인, echo 억제 창 없음, 호스트 명령 모으기 + 초당 제한 — `plan.md` 참고
- 62–65 (Phase 10): 레지스트리 없이 arm64 이미지를 SSH로 보내 호스트 클론에서 `deploy.sh`(헬스 체크 · 롤백), Cloudflare → 호스트 Caddy → 127.0.0.1:8090과 `CF-Connecting-IP` 기반 client IP, WebSocket ping 30초, `.env.production` · 태그 릴리스 — `plan.md` 참고
- 58–61 (Phase 9): 메시지 삭제는 보낸 사람 · 호스트, 실제 삭제 + `chat:delete`. 신고는 볼 수 있던 대상만 저장(운영 화면 없음). 계정 삭제는 비밀번호 재확인 후 즉시 완전 삭제(FK cascade), 토큰·소켓 즉시 무효. 개인정보처리방침 초안 — `plan.md` 참고
- 53–57 (Phase 8): 리액션은 채팅 메시지의 한 종류, 채팅은 모든 멤버 연결로, 읽지 않은 수는 서버 순번 기준, 알림 끄기는 멤버별 서버 저장, 기록은 커서 페이지 — `plan.md` 참고
- 50–52 (Phase 7): Laftel도 기본 꺼짐 · 선택 권한 · 따라가는 탭에만 주입(provider별 켜기), contentId `작품/에피소드`, Laftel은 seek함 — `plan.md` 참고
- 45–49 (Phase 6): Netflix는 기본 꺼짐 · 선택 권한, 따라가는 탭에만 주입, 재생/일시정지만 (seek 안내), provider별 view, 채팅은 side panel — `plan.md` 참고
- 41–44 (Phase 5): 합류는 요청 → 초대, 차단 시 호스트가 아닌 쪽이 빠짐, IN_ROOM 없음 · DND 보류, Desktop 트레이 · 알림 — `plan.md` 참고
- 33–40 (Phase 4): YouTube는 사용자 탭의 `<video>` 제어, URL은 contentId로 생성, content-change, 광고 중 명령 없음, 동의 화면, Platform 주입, side panel ⇄ content script port, 채팅 저장 — `plan.md` 참고
- 29–32 (Phase 3): Extension은 side panel이 소켓 소유, refresh token은 `storage.session`, 화면은 `packages/ui` 공유, 최소 권한 — `plan.md` 참고
- 18. MySQL은 FK `ON DELETE CASCADE` 컬럼에 CHECK를 허용하지 않아, 자기 자신 대상 요청/차단 금지는 서비스 계층에서 검증
